# SlopLens

在你自己的浏览器里给 X 时间线打一个「空话指数」：**分高的角标提示，拿不准的只留个记号，绝不替你下判决。**

纯本地规则引擎，零网络请求、零账号、零 API key。

> 本文档是**完整规格**（阈值、判据、已知的坑）。安装步骤与许可见仓库根目录
> [README.md](../README.md)，数据怎么处理见 [PRIVACY.md](../PRIVACY.md)。

---

## 它不是什么

- **不是「AI 检测器」**。它不说「这是 AI 写的」，它说「这条内容的可判定信号有多强」，而且永远把理由一起给你。
- **不上传任何东西**。没有服务器，没有 key，没有遥测。所有打分在页面里完成。

## 为什么这样设计

单条推文只有 280 字符，信息量不足以支撑「是 / 不是」的判决。任何声称能判准的工具，误伤率都会高到你不敢用。

所以这里退一步：**三档 + 给理由 + 可调阈值**。你永远知道它为什么这么标，也永远可以不同意它。

## 四档 + 两个记号

分数叫**空话指数**，0–100，**越高越空**——它是「这条内容有多套路化」的分数，不是质量分。

> 阈值判的就是这个数字本身。之前用过一个加权合成分，结果出现「界面显示 50 分却不标记」的矛盾，
> 已经改成：**显示的数字 = 判定用的数字**。具体信息只在折叠时当第二道闸。

| 档位 | 判定依据 | 界面上长什么样 |
|---|---|---|
| **空话较多** | 空话指数 ≥ 70 | 红色角标「空话 82」；「折叠」模式下会折叠，点一下展开 |
| **存疑** | 45 – 69 | 黄色角标「存疑 51」，**绝不折叠**，只提示 |
| **低信息** | 具体信息 ≤ 阈值（popup 可调 15/30/45），且空话没命中 | 灰蓝色虚线角标「低信息 18」，**绝不折叠** |
| **正常** | 都不命中 | 什么都不显示（诊断模式下会显示「具体 NN」） |
| **需展开**（记号） | 这条被 X 截断了 | 极淡的「需展开」记号，不可点，**不显示分数** |
| **半截**（记号） | 作者只发了前半段，后半段在自己的回复里 | 极淡的「半截」记号，不可点，**不显示分数** |

灵敏度在 popup 里切换，「低 / 中 / 高」对应三套阈值（见 `content.js` 顶部 `PRESETS`）。
觉得吵就调「低」，觉得漏就调「高」。低信息和不完整这两个档各有一个开关，不想要可以关掉。

### 「低信息」为什么不折

空话指数量的是**套路化**，低信息量的是**有没有料**。两件事不一样：

- 真人吐槽、开玩笑，本来就没数字没引语 → 低信息，但绝不折叠
- AI 写的带数据报告 → 空话不高，也不该折

所以「低信息」只标记、不折叠，而且**一条推最多一个角标**：空话已经命中的，就不再叠一个「低信息」。

阈值是三档（`strict 15 / mid 30 / loose 45`），因为「多少算没料」因人而异。
默认 `mid 30`——最初用的 20 在真实 feed 上一条都没触发（真人推文多少都有点数字或时空细节）。
诊断模式会把没标记的那批显示成「具体 NN」，直接看出为什么不触发。

### 「需展开」「半截」为什么不算分

两种都属同一类：**内容不完整，判了也不可信**。

- **需展开**：被 X 截断，`innerText` 只有可见的一段。一条长文可能因为「只剩 40 字 + 没数字」被算成低信息。
- **半截**：作者故意只发前半段，后半段在自己的回复里。能看到的字确实是作者打的，但内容没说完——
  真正有料的细节在回复里，按这半段打分必然偏低。

所以这两类**既不折叠、也不算低质**，只留记号。诊断导出里仍然记着分数（`truncated` / `partial` 两个字段），方便以后回看。

半截的识别只看**强信号**，宁可漏也不误标：

| 信号 | 例子 |
|---|---|
| 显式序号 | `（1/2）`、`接下文`、`见下条`、`未完待续`、结尾 `👇` |
| 悬空结尾 | 以 `，` `、` `…` `——` `...` 结尾，**且**整条 ≥ 16 字 |

「今天真热啊」「就这样吧…」这类短句不标——中文推文本来就很少写句末标点，按「结尾没句号」去判会把半个 feed 都标上。

### 折叠条件为什么是两个数

「低质量的 AI 内容」其实是两件事同时成立：

| | 套路化高 | 套路化低 |
|---|---|---|
| **具体信息低** | ✅ 这里才折叠 | 真人写的空话 → 不折 |
| **具体信息高** | AI 写的但有用 → 只标记 | 正常内容 |

所以折叠要求 `套路化 ≥ 70 且 具体信息 ≤ 35`。
只有套路高、但内容有料的（例如 AI 写的带数据报告），只加角标，**不会被收掉**。

反过来说，这也意味着：只判断「是不是 AI」是不够的——AI 写的有用内容你不该折，真人写的空话你也不该折。

### 两个阶段，别用同一套设置

| | 目的 | 该怎么设 |
|---|---|---|
| **判定阶段**（现在，你自己用） | 看清每一条到底是什么，攒数据 | 只标注 + 诊断模式，**别开折叠** |
| **交付阶段**（给别人用） | 自动把低质 AI 内容收掉 | 折叠空话 + 灵敏度「高」 |

**角标位置**也可以在 popup 里改：

| 位置 | 长什么样 | 适合 |
|---|---|---|
| **时间旁边**（默认） | 挂在「名字 · @handle · 时间」那一行的末尾，紧凑样式 | 想让正文保持干净 |
| **正文下方** | 独立一行，带完整说明文字 | 想要更明显的提示 |

面板（判定依据、反馈按钮）始终渲染在正文后面，不会撑坏 header 的 flex 行。

## 反馈协议（这是整个项目最重要的一步）

角标点开有三颗按钮。**你只需要做三种动作，而且不用判断「像不像 AI」**：

| 你的感受 | 点什么 | 价值 |
|---|---|---|
| 一眼假，能说出依据 | `这是 AI` | 普通正样本 |
| 有具体细节、亲历、口语 | `这是真人` | 普通负样本 |
| **觉得怪，但说不出哪怪** | `说不清` | ⭐ 最值钱 |
| 没什么感觉 | **什么都不用点** | 不产生数据，也不产生噪声 |

「说不清」那几条是**人类盲区**，也是模型唯一能提供增量的地方。别硬判——硬判会把数据污染掉。

刷两天，攒 15–30 条，然后在 popup 里点「导出反馈样本」，会得到一个 JSON。把它发我，就是下一版（T1）的训练与评测数据。

## 已知局限（别当成 bug，是设计取舍）

- **只支持 X**。知乎适配器在路线图里。
- **纯规则 T0**：明显的套路话抓得住；被 prompt 改写过的、隐蔽的会漏。这是预期行为——T0 的任务是「先把最刺眼的那批消掉，且绝不误伤」。
- **文案簇查重只在单次会话内**（刷新后重置），跨会话去重要等 T1。
- **公文 / 通知 / 学术摘要容易落到「存疑」**。它们和 AI 输出在结构上几乎同构，这是规则法的天然软肋，宁可漏也不误折叠。
- **X 的 DOM 会变**。选择器集中在 `content.js` 的四个函数里：`ownTextEl` / `tweetId` / `handleOf` / `isTruncated`，改这四个就行。
- **「需展开」靠 X 的 `data-testid` 认**（`tweet-text-show-more-link`），X 改名了就会退化成按「显示更多」文案匹配；两个都失效时，长推会被当成短推打分，也就是回到 0.6.0 的行为。
- **「半截」只看文本，不看 DOM**。所以它认的是「作者写了续篇标记」和「句子明显没说完」这两种情况；作者什么标记都不留、结尾又刚好写了句号，就会漏掉。这是故意的——宁可漏，也不要把所有短句都标上。

## 阈值怎么标定

`PRESETS` 里那几个数（`high` / `mid` / `foldSpec`）一直是拍的。攒到 20 条以上人工标签之后，
可以让数据自己说话：

```bash
node tools/calibrate.mjs samples.json                        # 只喂标注样本
node tools/calibrate.mjs samples.json --background diag.json # 再喂一份真实 feed（强烈建议）
```

输入直接吃 popup 里「导出反馈样本」的数组，或者「导出诊断数据」那个对象（脚本自己认形状）。

**四条原则，改了就等于把这个工具变成另一种东西：**

| 原则 | 为什么 |
|---|---|
| 分数一律**重算**，不信存档里的 `score` | 存档的分数是老版本引擎算的，引擎一改就过期 |
| **不用 argmax** 挑阈值 | 二十几条样本上任何 argmax 都是过拟合。脚本找的是「真人折叠 = 0」的整个稳定区间，取中点，不取端点 |
| 只信 `labelSource === 'human'` | `ai-confirmed` 是模型判的，拿它标定等于让模型给自己打分 |
| 必须喂**背景样本** | 人只会去标「值得标」的，标注集全是边界案例。没有背景分布，学出来的 `mid` 会把半个 feed 标成存疑 |

脚本会告诉你 `mid` 是被哪条约束卡住的（真人存疑、还是背景被标比例），
不给理由的数没法复核。

> **标定不等于该改。** 样本少的时候它会一本正经地给出一个数——
> 那个数是「这批样本上的最优」，不是「你该用的」。改完记得重跑 `test/run.mjs`，
> 真人折叠必须仍然是 0。

## 深检（可选 · 用自己的 key）

插件默认完全不联网。如果你想要第二意见，可以在设置里填一个 **OpenAI 兼容**的接口，然后点推文面板上的「深检」。

支持所有 OpenAI 兼容服务。**默认是 DeepSeek V4.1 Flash**，开箱即用：

| 服务 | 接口地址 | 模型名 |
|---|---|---|
| **DeepSeek（默认）** | `https://api.deepseek.com` | `deepseek-flash` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 本机 Ollama | `http://localhost:11434/v1` | `qwen2.5:7b`（key 留空） |
| 任意 one-api 网关 | 你自己的地址 | 看网关 |

> **模型名别填错。** 界面上叫 V4.1 Flash，但 API 的模型名是 `deepseek-flash`。
> 旧名 `deepseek-v4-flash` 目前仍可调用，但官方要求用新名；填 `deepseek-v4.1-flash` 会报错。

> **思考模式已自动关闭。** DeepSeek 的思考模式默认是开的、effort 默认 `high`，
> 分类任务根本用不上，白等好几秒。插件识别到 `deepseek.com` 域名时会自动带
> `{"thinking": {"type": "disabled"}}`；其他服务商一个字都不多发。

**几个必须知道的设计取舍：**

- **深检不改变折叠决策**。它只是面板里多一块信息，不会因为模型说「高」就把这条折叠掉。原因很简单：模型也会错，而折叠是有代价的动作。
- **只在点击时调用**，不会后台自动跑。所以你刷 500 条，花费是 0；点 10 次，才是 10 次。
- **有每日上限**（默认 200 次），超了就不发请求，直接告诉你「今天的额度用完了」。
- **可选 few-shot：把标过的样本回灌 prompt**（默认关）。这是 T1 训练之前唯一能当天见效的用法。
  选样本四条规则，全往保守偏：只认 `labelSource === 'human'`（`ai-confirmed` 是模型自己判的，
  回灌等于拿自己的偏见给自己校准）；只认 `ai` / `human`（`unsure` 当标签是噪声）；跳过截断 / 半截；
  低于 20 字不要。每类最多 4 条、每条 160 字，满配约多 1300 输入 token。
  **默认关**是因为它改变了「只发你点的那一条」这个承诺——开关在 popup 的深检面板里，
  旁边直接写着当前可用几条。
- **prompt 里明确禁止它判断「是不是 AI」**。它只评两个维度：`具体信息量` 和 `模板化程度`。这是产品口径——「是不是 AI」不可证伪，而这两个维度可验证。
- **key 是明文存的**。`chrome.storage.local` 里就是明文，任何能读你磁盘的人都能拿到。这一条没法美化。
- **权限是运行时申请的**。你填哪个域名，插件就只申请那一个域名的访问权，不会要 `<all_urls>`。

### 为什么 key 不能放在页面里

content script 的 `fetch` 继承页面源，直接调 `api.openai.com` 会被 CORS 拦。所以请求走：`content script → sendMessage → background service worker → fetch`。key 永远不出现在页面上下文中。

## AI 预判（判定加速）

人判一条要读完整条，还要回想，慢是必然的。让模型先给一个**初判 + 证据**，你只做「采纳 / 否决」，能快很多。

两个入口：

| 入口 | 位置 | 适合 |
|---|---|---|
| 单条 | 点开角标 → 「AI 预判」 | 拿不准的那几条 |
| 批量 | popup → 「AI 预判本屏」 | 一次过一遍当前屏 |

### 规则（写在 `llm.js` 的 `JUDGE_SYSTEM` 里）

四个维度，各 0-3 分：

| 维度 | 越高越像 | 看什么 |
|---|---|---|
| **A 结构规整度** | 机器 | 条目长度是否一致、有没有成套并列、句子长度起伏是否异常小 |
| **B 词汇套路** | 机器 | 时代开场白、综上所述、抽象名词堆叠、「不是X而是Y」 |
| **C 信息具体度** | 真人 | 数字、时间、地点、人名、引语、亲历细节 |
| **D 语域自然度** | 真人 | 口语、俚语、错别字、情绪化、跑题、反讽 |

判定规则：

- `C + D ≥ 5` → **human**，即使 A+B 也高（AI 写的内容里也可能有料）
- `A + B ≥ 5` 且 `C + D ≤ 2` → **ai**
- 去掉链接和标签后不足 80 字、证据不足 → **unsure**
- 其余一律 **unsure**（宁可不确定，不要错标）

### 明确禁止的判据

单个破折号、正式书面语、非母语者的语法、段落整齐、单个 emoji、文中出现「AI」这个词。

**公文和 AI 输出在结构上高度同构**，这是所有检测器的共同误判源，所以规则里专门禁掉了。

### 这套规则从哪来

- **DivEye**（[arXiv 2509.18880](https://browse-export.arxiv.org/abs/2509.18880)）：人写的文本在「不可预测性的起伏」上更丰富，LLM 输出更平。所以 A 维度专门看节奏。
- **Short-PHD**（[arXiv 2504.02873](https://export.arxiv.org/abs/2504.02873)）：短文本检测天然不稳，需要补上下文。所以短文本一律倾向 unsure。
- 已知失效模式：正式书面语与非母语写作会被系统性误判，对应上面那节禁用判据。

### 一个不能省的字

样本里会记 `labelSource`：

- `human` —— 你自己点的
- `ai-confirmed` —— AI 判的，你只点了采纳

**这两类标签在训练时不能同等对待。** AI 确认过的标签带着模型自己的偏见，将来训出来的分类器会系统性地偏向「这个模型认为的 AI 味」。所以来源必须留痕，T1 训练时要降权或分层评估。

## 代码结构

```
manifest.json     MV3 配置（含 optional_host_permissions）
engine.js         规则引擎（纯函数，零依赖，可单独在 Node 里跑）
llm.js            深检客户端（OpenAI 兼容，注入 fetch，可在 Node 里 mock）
content.js        X 适配器 + 角标/折叠/面板 + 反馈落库 + 深检按钮
styles.css        注入样式
popup.html/js     设置、统计、样本导出、key 配置
background.js     service worker：右键菜单 + 代调 LLM（避开 CORS）
tools/calibrate.mjs 用标注样本反推阈值（0 依赖）
test/run.mjs      引擎回归（0 依赖，违反硬约束会 exit 1）
test/llm.test.mjs LLM 客户端测试（0 依赖，起本地假服务）
test/calibrate.test.mjs 标定脚本回归（0 依赖）
test/dom.test.mjs DOM 冒烟（需要 jsdom）
```

`engine.js` 和 `llm.js` 都刻意不依赖 DOM 和 storage，所以能在 Node 里直接跑测试——接模型的时候这一点很省事。

## 路线图

- **T1**：用攒下来的样本训练线性权重表（TF-IDF + LinearSVC → JSON），纯 JS 推理，不需要 WASM。目标是把「隐蔽 slop」的召回从现在的水平拉上去，同时把公文误伤压回 0。
- **P2**：灰区自动深检（只对 0.4–0.7 的样本调用，且要过预算闸）、跨会话文案簇去重、读取 X 自带的「Made with AI」标记。
- **P3**：知乎适配器。同一个引擎，换选择器 + 中文特征。

- **v0.6**：空话指数改为直接等于套路化分（显示与判定统一）；「无具体信息」权重下调；中英混排术语计入具体信息；诊断导出补全两个维度
- **v0.5.1**：默认模型改为 DeepSeek V4.1 Flash（`deepseek-flash`），自动关闭思考模式提速
